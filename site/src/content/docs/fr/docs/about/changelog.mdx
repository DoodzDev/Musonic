## Comment les versions sont organisées

L'appli, le lecteur web et le serveur sont dans le même dépôt, mais sortent séparément, chacun avec son propre numéro de version et son propre préfixe d'étiquette.

| Étiquette | Nom de la version | Fichiers |
|---|---|---|
| `mobile-vX.Y.Z` | Musonic Mobile X.Y.Z | `Musonic.apk`, l'appli Android |
| `web-vX.Y.Z` | Musonic Web X.Y.Z | `Musonic-Web.zip` (à servir à la racine d'un site) et `Musonic-Web-app.zip` (installé par la console de Musonic Server, servi à `/app/`) |
| `server-vX.Y.Z` | Musonic Server X.Y.Z | `compose.yml`, et le programme pour Linux x86 et ARM (`musonic-server-…-linux-x86_64.tar.gz`, `…-aarch64.tar.gz`) avec sa console à côté |

- **La version marquée « Latest » sur GitHub est toujours l'appli Android.** Ainsi, le lien de téléchargement `releases/latest/download/Musonic.apk` donne toujours l'appli la plus récente, même quand une version du serveur ou du lecteur web est sortie après.
- **Le serveur est aussi publié en image Docker**, `ghcr.io/doodzdev/musonic-server`, avec les étiquettes `X.Y.Z`, `X.Y`, `X` et `latest`. Par exemple, la version 1.2.1 porte les étiquettes `1.2.1`, `1.2`, `1` et `latest`.
- **La console d'administration n'a pas de version publiée à part** : elle est livrée dans chaque version du serveur et dans l'image Docker.
- Avant le 2026-10-12, les versions de l'appli étaient étiquetées `vX.Y.Z` ; elles ont été renommées `mobile-vX.Y.Z` ce jour-là.

## Lire un numéro de version

Chaque partie suit le [versionnage sémantique](https://semver.org/lang/fr/) : `MAJEUR.MINEUR.CORRECTIF`.

- **CORRECTIF** (1.2.0 → 1.2.1) : uniquement des corrections.
- **MINEUR** (1.1.0 → 1.2.0) : de nouvelles fonctions, toujours compatible avec la version précédente.
- **MAJEUR** (1.x → 2.0) : un gros changement, qui peut ne plus marcher comme la version précédente : lisez son journal avant de mettre à jour.

Les journaux suivent le format [Keep a Changelog](https://keepachangelog.com/fr/1.1.0/) : chaque version liste ce qui a été ajouté (**Added**), modifié (**Changed**), corrigé (**Fixed**) et, si besoin, les correctifs de sécurité (**Security**). Quand une fonction d'une appli demande un serveur récent, le journal indique quelle version du serveur.

<Aside type="tip">
Pas besoin de surveiller cette page. L'appli Android vérifie les nouvelles versions (profil, puis **À propos**, puis **Vérifier les mises à jour**), et la console de Musonic Server affiche sur son tableau de bord, dans la carte **Versions**, la version installée et la dernière parue sur GitHub.
</Aside>
